# 调研与多样性规则

## 前置研究

先读历史索引及关联当前文档，再搜索网上原始源码。新套题内容创作必须在候选审查之后；不要让现成题目限制搜索到只会证实自己的答案。

默认 N 道题：至少 3N 个真实、去重候选范围；至少 min(N,8) 类领域或用途；目标至少 ceil(N/2) 个独立上游项目。候选可以是项目内明确可抽取的组件，但不同路径指向同一实现、同仓库不同分支或镜像不能凑数。每个最终方向对照至少两个独立实现。

优先依次考虑：可运行的已有作品；成熟项目的可独立理解组件；官方实例；维护良好且许可清楚的教育项目。题型应有真实约束，不能把大型仓库拆成没有学习价值的调用练习。搜索列表只作发现入口，必须回到原仓库阅读。

用多轮检索补齐空白：先按不同领域检索，再按已有候选缺少的算法、工程能力或成果类型检索。中英文都可使用；不要宣称已穷尽互联网。记录候选去重方法、搜索词、原始 URL、日期、版本、读取范围、筛选结论。保存低分及无法验证的候选，以便说明淘汰依据，但它们不得进入合格来源库。

同时记录候选的实现语言；多语言组合按各目标语言补齐生态检索，优先真实的惯用实现。原有研究数量和集中度要求按整套题计算，不按语言重复计算；仍须为每个题目方向比较至少两个独立实现。跨语言使用遵循语言适配规则，不用移植关系伪造独立项目。

若只有 12 个合格方向，不交付“已符合规则”的 15 题；继续研究，无法补齐则报告可用范围和具体缺口。不能以“时间不足”为理由给未知项目 85 分。

## 四个覆盖维度

- `domain_tags`：实际应用，例如教育、媒体、无障碍、地理空间、科学计算、开发者工具。
- `concept_tags`：主要算法或计算概念，例如区间代数、有限状态机、误差传播、空间索引。
- `artifact_tags`：成果形式，例如 CLI、HTTP API、浏览器界面、GUI、SVG、音频、数据文件、交互图表。
- `engineering_tags`：工程方法，例如属性测试、协议分帧、离线优先、资源管理、事务、可访问性、插件接口。

使用简短稳定的英文标签，小写并用连字符连接；它们是索引，不必直接展示给学习者。先查看历史使用的标签。state-machine 与 finite-state-machine 不能被当成不同创新；Web API 与 HTTP API 统一为 http-api。更换自然语言标题不会改变计算问题。

语言记录放在独立元数据字段，不能把 python、cpp、rust 或框架名称放入这四个维度冒充广度增量。跨所有语言历史比较；不得为新语言清空旧题。真实新增的所有权约束、接口协议或资源管理训练可按实际验收目标标注，同义方法仍须归并。

## 默认可计算检查

N=15 时至少覆盖 8 类领域、8 类核心概念、5 种成果、5 类工程方法；小批次下界分别取 min(N,8)、min(N,8)、min(N,5)、min(N,5)。每题至少填一个各维标签，人工审核避免无关标签堆砌。

相对全部历史，实质扩展单元至少 min(3,N) 个，涉及至少 min(2,N) 个维度；至少 ceil(0.4N) 题含真实扩展。单元可为新增规范标签，或一个经过审阅的新组合/约束深化；不能靠重命名标签凑数。

使用已有标签构成新组合时，逐题提供 novelty_evidence：kind（combination/constraint/depth）、compared_ids、至少两个 axes、delta、acceptance 和 review（approved、reviewer、evidence_ref）。说明相对旧题的可验收新要求；组合必须未出现在历史中，按所选维度的实际标签组合去重计数。程序检查结构与组合差异，语义价值仍由审阅者核实。原相似度 0.75 和核心重复阻断保持；高相似度深化需重设计，不能通过这个字段覆盖重复判定。复习与跨语言直译可作为复测，但不计新增题或覆盖。

相似度为四维集合 Jaccard 的加权和：核心概念 0.45，工程方法 0.25，领域 0.20，成果 0.10。与历史或同套任一题达到 0.75 时退回重设计；概念集合和工程方法集合都完全相同也退回，即使换了场景与输出。该计算只是筛查，还必须人工排查“同一个算法换皮”。

每题保存最相似的旧题标识及新增学习价值。基础知识会复用，但应改变一个实质性设计问题。例如“另一个任务清单”不是新方向；引入冲突合并并把它作为核心验收目标，才可能形成新的训练问题。

单一领域的明确用户请求：在计划中填 `single_domain_reason` 并引用用户本次限制，领域下界可放宽到 1。仍需满足其余维度与累计增量，不能将此字段用作省略调研的后门。其他广度指标需要用户明确修改后才能调整；不能由执行者为了通过检查自行降低。

## 来源集中度和可学性

默认一套中，任何一个上游项目支撑的题目不超过 ceil(N/5)，同时至少 ceil(N/2) 个不同上游项目。一个大合集中的多个函数不代表多个独立项目。若领域有限，优先扩展检索而不是隐瞒来源集中。

在符合质量的前提下选择能教会不同思考方式的来源：算法推导、数据建模、交互设计、协议、数值验证、工程取舍等。难度来自约束与推理，不来自冗长安装、罕见语法或大量粘贴。
