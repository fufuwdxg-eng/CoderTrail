# 题目与文档交付

## 每题的最小结构

1. 标题、难度、建议时长、目标语言及版本、学习目标与该语言的先修知识。
2. 真实或合理的应用场景，说明为什么需要这个程序。
3. 可验收的必做需求，明确最小版本；把可选功能分开。
4. 输入输出与失败条件：类型、单位、范围、编码、顺序、状态、副作用与性能规模。
5. 至少一组可手算或独立核对的输入输出；需要文件时给出完整最小数据或可复现生成方式。
6. 正常、空输入、边界、错误输入；适用时加入随机、并发、数值误差、恢复和重复执行检查。
7. 分层提示：先提示建模，再提示关键数据结构；题目区不放完整实现。
8. 一个增加思考深度的拓展与一个设计复盘问题。
9. 来源评估 ID、借鉴范围与许可说明；详评在题目后，完整答案统一文末。

## 参考实现

为每题提供可独立执行的完整代码、构建/运行/测试命令、工具链、依赖与版本说明、演示输入输出。多个文件必须给清目录与完整文件内容，包括必要的头文件、构建配置、依赖清单、初始化数据和测试。使用目标语言标准库与基础工具是优先项，不是为了避免真实项目而强制删去有价值的生态工具。每个命令标注工作目录和适用系统；不把 Python 运行命令套在其他语言上。

多语言分题时为每题给出其独立环境；多语言协作时说明各组件责任、启动顺序、接口约定和集成测试。若同一题提供多个语言版本，每版都要完整源码与独立评分/运行证据；题数只计一次。编译、类型检查成功不能代替运行验收。环境缺失就记录未完成，不能交付“已验证”的伪代码。

不把上游庞大项目整份搬进文档。选择已评分的明确范围，保留关键设计并做教学化简化，说明删去的能力与适用边界。改变算法、输入合同或错误处理后重新验证，不能靠上游测试结果背书新实现。

为图形、音频、GUI 等项目实际检查生成成果或操作过程；函数返回成功不等于体验正确。不要自动播放音频。对随机和浮点输出使用合理的性质、误差阈值与固定种子，不要求不应保证的跨平台逐字节一致。

代码保存说明必须真能执行。说明文字与源码分开，按目标语言使用正确的注释符号、文件扩展名、入口和编码；实际测试文档中指示的保存与运行路径。避免输出默认立即删除，却不告诉学习者怎样保留。

## 文档结构

学习说明 → 15 题总览与兴趣路线 → 全部题目 → 来源九维评分摘要与新增覆盖 → 复盘与参考资料 → 全部参考代码。

总览列出语言分配与所需环境；答案按题号和文件路径组织，不按语言拆散同一个项目。所有语言的完整代码仍集中在文末，构建说明不能泄露题目区完整答案。

摘要表至少列评估对象/范围、固定版本、九维分数、总分、通过/待审/淘汰结论。正式采用项必须通过；不要为表格美观隐去关键限制。许可证及必要声明在答案区或关联源文件保留。

使用 documents 技能排版、渲染并逐页检查。先决定可读的代码字号和行宽，再决定页数。不要提前承诺固定页数。将长代码在完整函数或清晰区块之间续页，保留复制后的缩进。

完成后提取 Word 中全部源文件、配置与测试，与被测文件逐一作字节级核对（仅允许明确记录的换行归一化；有对应语言解析器时可辅助结构核对），在各自工具链重新构建和运行提取结果。不要用 Python AST 验证其他语言。确认题目接口、样例、代码行为与文档页码相符。默认交付 Word 与配套源码/评分工具包；从相同快照生成，渲染图片与内部 PDF 用作检查。源码包不携带个人题库或既往学习记录。

源码包通过评分程序 package 命令生成；附验收清单、工具及空学习记录。学习者可先用 learner 模式得到功能诊断，再补九维审阅，不把未评分维度当成满分。

## 持久结果

保存最终文档、机器可读的研究/评分记录及必要复现证据；大日志或外部源码只保存有明确用途且许可允许的部分。题库索引保存持久引用、版本、哈希和评估关联，不填会失效的临时目录作为唯一来源。

文档制作或目标位置保存失败时，保留已完成工作，明确报告哪一步未完成；不得把未交付题目登记为已交付。合格来源评估可先入库，出题历史只在成品保存后记录。
